How to use this

Read me first

This is a forensics triage tool I wrote while studying for the GCFE. You give it a copy of a computer's files and it hashes everything, builds a timeline, spots files in disguise and faked dates, recovers deleted files from a raw disk image, and keeps a tamper-evident log of what it did. I built it so that someone who is not a forensics expert can see quickly what happened on a machine, and trust that the evidence was not changed along the way. The case you are looking at is invented (an employee copying files to a USB stick), so nothing real is exposed.

Try this in 60 seconds

  1. Start on "The case" tab. Read the Case summary card, then the "What happened, in order" strip on the right. It tells the story in a short list: an employee gathers files, renames an archive to look like a photo, copies it to a USB stick and deletes the originals. The "Show the other 9" button under it lists the rest.

  2. Click the red stamp marked "1 critical". It jumps to "What I found" with just one finding: invoice_template.pdf, a file whose hash is on a known-bad list. Notice the "1 of 20 findings" count, then click "Start over" to see all twenty.

  3. Click the card "Extension does not match content: holiday_photos_2025.jpg". A panel opens with "In short", "Why I flagged it" and "What to do about it". The file is named like a photo but its contents are a ZIP archive. Under "Files involved", click holiday_photos_2025.jpg to see its three hashes (MD5, SHA-1, SHA-256) and a line saying an identical copy was recovered from deleted space. Then press Close.

  4. Open "More of the file" in the left-hand tabs, then "Deleted, then found", and click the first row, CF-001. It is a 6,342 byte ZIP pulled out of the raw disk image. The panel says it is the same as holiday_photos_2025.jpg on disk, matches a Recycle Bin record for proj_backup.zip, and holds three files. So the "photo" is the deleted archive.

  5. In "More of the file", open "Did I change anything?" and click "Check the chain here". It says the chain is intact. Now click "Pretend someone edited an entry", then "Check the chain here" again. It reports the chain is broken at entry 3. Click "Undo" to put it back. That is how you can tell a log was edited.

Words you will see

Triage
A fast first pass to find what matters before anyone starts a slow, deep investigation.
Evidence, read-only
The copy of the files being examined. The tool opens it so it can look but not change anything.
Hash (MD5, SHA-1, SHA-256)
A fingerprint worked out from a file's bytes. Change one byte and the fingerprint changes completely, so two files with the same fingerprint are the same file.
Known-bad hash
A fingerprint on a list of files already known to be malicious. If a file matches, it is that file, whatever it is called.
Chain of custody
The written record of who handled the evidence and when, so you can show it was not altered.
Hash chain
How my custody log protects itself. Each entry carries the fingerprint of the entry before it, so editing one entry breaks every entry after it.
Timestomping
Changing a file's dates to hide when it was really made or edited. I compare two sets of dates ($STANDARD_INFORMATION and $FILE_NAME) because one of them is harder to fake.
MACB
The four times a file keeps: Modified, Accessed, Changed (its record) and Born (created). It is a column on the Timeline.
File in disguise
A file whose name says one thing and whose first bytes say another, like a ZIP named .jpg. The first bytes are called the signature.
File carving
Recovering deleted files by scanning the raw disk for the start of known file types, without needing the file table.
Unallocated space
Parts of a disk not assigned to any file. Deleted data can sit there for a long time.
MFT
The Windows file index. It still has entries for deleted files, which is how I match recovered files to names.
Prefetch
A Windows record of which programs have run and how often. It is how I know the archive tool and the secure-delete tool ran.
IOC (indicator of compromise)
A clue such as an IP address, web address, email or hash that points to something bad. They are listed on the Clues tab.
MITRE ATT&CK
A public catalogue of attacker techniques, each with an ID like T1036. I tag each finding with the ones it looks like.
UTC
The world standard time. Every time on this page uses it, so nothing depends on a time zone.

What this shows about my skills

I can explain forensics ideas like hashing, timestamps and chain of custody in plain words, which is most of the job when someone in an IT support role is asked "what happened to my files?". I write careful, read-only code, check it against an answer key, and the tool says "weak" when the evidence is weak instead of overclaiming.

Why I built this

Why I built this

I'm a computer science student in Toronto and I'm teaching myself digital forensics, mostly because I want to sit the GCFE one day. Reading about Windows artefacts only got me so far. I kept nodding along at things like $STANDARD_INFORMATION versus $FILE_NAME and then realising I couldn't explain them to anyone. So I wrote a tool that has to deal with them.

Timestomping tripped me up the most. My first version called any file that was modified before it was created a fake, and that is exactly what a normal copy looks like. Now it wants several signs at once before it says anything strong. File carving was humbling too. Finding the end of a JPEG sounds easy until a thumbnail inside it ends the file early.

All the data here is made up, and I graded the tool against my own answer key, so read the results as "it does what I meant" and not as proof it works on a real case. Next I'd like to run it on a public disk image, carve more than four file types, and read real Prefetch and registry files instead of exports.

Diogo
